# Лабораторні зі скриптових мов програмування

Скалоцький Андрій Русланович, Кб-205. Лабораторна 1, варіант 13.

Три консольні модулі: аналіз паролів, контроль доступу, реєстрація
та вхід із CSV-базою і JSON-журналом. Потрібен Python 3.10 або новіший.
Перевірено на Python 3.12.14.

## Перший запуск на Windows

Розпакуй архів і відкрий саме папку `cybersecurity-python-labs` у VS Code
через **File → Open Folder**. У ній мають бути `requirements.txt`,
`shared` і `labs`. Далі **Terminal → New Terminal**.

У PowerShell виконай по черзі:

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m labs.lab01.main --seed 13
```

Якщо команда `py` не знайдена, спробуй `python -m venv .venv`.
Якщо PowerShell блокує активацію, вибери **Command Prompt** у меню
створення термінала VS Code й активуй середовище так:

```bat
.venv\Scripts\activate.bat
```

Інші команди залишаються такими самими. Запускати `main.py` кнопкою
Run Python File не потрібно: проєкт запускається як пакет із кореня.
`--seed 13` відтворює приклад зі звіту; без цього параметра індекси випадкові.

## Окремі завдання та перевірки

```text
python -m labs.lab01.main --task 1 --seed 13
python -m labs.lab01.main --task 2
python -m labs.lab01.main --task 3
ruff check .
ruff format --check .
python -m unittest discover -v
```

За потреби форматування: `ruff format .`, автоматичні виправлення:
`ruff check --fix .`. Усе виконується в активованому `.venv`.
У `pyproject.toml` явно ввімкнено перевірки E, F, I та D:
стиль, базові помилки, імпорти й docstring. Довжина рядка - 79.

## Як працює демонстрація

1. Завдання 1 бере 10 паролів варіанта й додає 3 копії.
   Для seed 13 індекси від 0: `[4, 9, 2]`. Увесь список має 13 елементів.
   Повтори рахуються до виставлення оцінок, тому оригінал і його копія
   мають однакову категорію. Чотири окремі приклади після таблиці
   демонструють категорії, яких немає у вихідних даних.
2. Завдання 2 показує 10 ресурсів і 50 рішень доступу.
   Додатково перевіряються невідомий користувач і неактивний бот
   без блокування. Початкові дані варіанта при цьому не змінюються.
3. Завдання 3 записує 10 вигаданих користувачів у `users.csv`, читає
   базу й виконує 6 спроб входу. Очікувано: 1 успіх і 5 відмов.
   Кожна спроба додає подію в `log.json`, зокрема якщо виник виняток.

У завданні 1 мінімум 8 символів. У завданні 3 мінімум 14, алгоритм
SHA3-256, сіль `00013`. Це різні умови, вони не об'єднуються.
Пароль успішного навчального входу для `andriy_lab`: `RainyLviv@2026!`.
Це вигадані дані. Не використовуй у демонстрації справжні паролі.

**Повторний запуск завдання 3 перезаписує навчальну CSV-базу,
але доповнює журнал.** Тому після двох запусків у журналі буде 12 подій.
Шляхи до даних визначаються відносно `task3.py`, а не поточної папки.
Пошкоджений журнал не затирається: програма повідомляє про помилку.

## Уточнення неоднозначних умов

- Для допустимого за довжиною пароля 0 або 1 виконана вимога дає
  категорію «Слабкий», 2 вимоги - «Середній», усі 3 - «Сильний».
  Довгий унікальний пароль з усіма вимогами - «Дуже сильний».
  Так розмежовано категорії, які перетинаються в тексті методички.
- Довгий складний пароль із повторами залишається «Сильним».
  Умова прямо не задає цю гілку; пояснення виводиться поряд з оцінкою.
- Спеціальним вважається символ із `string.punctuation`; пробіл
  не зараховується. Окрема вимога малої літери в `criteria` відсутня.
- `args` і `kwargs` зберігаються в журналі, але пароль замінено
  на `[REDACTED]` як для позиційного, так і для іменованого аргументу.
- Задана сіль спільна для всіх користувачів цього варіанта.
  Отже, однакові паролі дадуть однакові хеші. Для справжніх систем
  потрібні випадкова сіль для кожного користувача і спеціальна
  функція зберігання паролів. Тут виконано навчальну умову SHA3-256.

## Скриншоти для звіту

Знімай свої результати після запуску на Windows:

1. Дерево файлів VS Code та `shared/student.py` з даними студента.
2. Активоване `.venv`, `python --version` і `python -m pip show ruff`.
3. `--task 1 --seed 13`: таблиця паролів разом з індексами копій.
4. `--task 2`: список ресурсів і приклади ALLOW та всіх причин DENY.
   За потреби зроби 2 скриншоти, прокрутивши термінал.
5. `--task 3`: таблиця хешів і результати 6 спроб входу.
6. Відкриті `users.csv` та `log.json` (у журналі видно маску пароля).
7. `ruff check .`, `ruff format --check .` і підсумок тестів `OK`.
8. Сторінка GitHub з файлами проєкту та адресою репозиторію.

після чого ті самі команди встановлення й запуску.
