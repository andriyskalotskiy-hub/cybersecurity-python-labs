# Лабораторна 4 — варіант 13

Консольна утиліта читає один запис CVE. У звіті показує оцінку CVSS 3.1
та вплив на цілісність. Запис отримує `review`, якщо бал не менше 6.0
і `integrityImpact` дорівнює `LOW`. Це правило для навчального відбору.

## Запуск

З кореня репозиторію, у середовищі з Python 3.12 або новішим:

```powershell
python -m pip install -r requirements.txt
python -m labs.lab04.main --cve CVE-2099-10001 --input labs/lab04/data/nvd_sample.json
```

Локальний приклад синтетичний. Очікується `other`: бал 9.8,
але вплив на цілісність `HIGH`.

Один ручний запит до публічного API, якщо NVD доступний:

```powershell
python -m labs.lab04.main --cve CVE-2021-44228
```

Ключ необов'язковий. Якщо `NVD_API_KEY` задано в середовищі,
клієнт передає його в заголовку `apiKey`. Не зберігайте ключ у Git.

## Результат

Програма виводить один JSON з ідентифікатором, варіантом, описом,
статусом NVD, версією CVSS, балом, джерелом, вектором, правилом,
спостереженим значенням і рішенням. Відсутні значення мають вигляд
`null`. Бере першу оцінку Primary або першу зі списку, якщо Primary немає.

- `not_found` — немає запису; `rejected` — запис відхилено.
- `insufficient_data` — бракує статусу, оцінки або потрібної ознаки.
- `review` — виконано обидві умови; `other` — умови не виконано.

Код завершення 0 означає, що звіт сформовано, 1 — помилку отримання,
читання або даних, 2 — неправильні аргументи чи номер варіанта.

## Перевірка

```powershell
python -m pytest labs/lab04/tests -q
ruff check labs/lab04
ruff format --check labs/lab04
```

Тести не звертаються до NVD. Для захисту можна окремо показати
`test_variant_13_threshold` (межа 6.0) і `test_invalid_impact`
(некоректна ознака) з файла `tests/test_analysis.py`.

Код розділено на три частини: `main.py` вибирає джерело й друкує звіт,
`api_client.py` виконує HTTP-запит, а `analysis.py` перевіряє отримані
дані та застосовує правило.
