# Захист лабораторної 3

Я зробив API реєстру знахідок хмарного аудиту. У SQLite дві таблиці:
категорії перевірки та самі знахідки. Для варіанта 13 це iam, storage і
network, а value — оцінка ризику від 0 до 10. Через FastAPI можна додати,
прочитати, повністю змінити чи видалити запис, застосувати фільтри та
додати пакет. Pydantic перевіряє дані до SQL; обмеження бази захищають
їх додатково. Якщо елемент пакета помилковий, скасовується весь пакет.

Код показувати так: `schema.sql` → `database.py` → `repository.py` →
`schemas.py` → `routers/records.py` → `main.py`. Початкові дані в seed.json.
Для демонстрації виконати seed, запустити Uvicorn і відкрити `/docs`.
Далі показати CRUD, фільтр, 422, 409 та відкат пакета.

## Контрольні питання

1. **Таблиця, запис, поле.** Таблиця містить однотипні об'єкти, запис —
   один об'єкт, поле — його властивість. Категорія має багато знахідок:
   зв'язок один до багатьох.
2. **Ключі.** Первинний ключ id однозначно визначає рядок. Зовнішній
   records.category_id посилається на categories.id. API повертає 404
   для неіснуючої категорії; SQLite додатково контролює FOREIGN KEY.
3. **SQLite і CSV/JSON.** SQLite має SQL, JOIN, індекси, обмеження та
   транзакції. CSV/JSON зручні для обміну, але не забезпечують цих
   можливостей самостійно.
4. **Параметри SQL.** Значення передаються окремо від SQL через `?`.
   Навіть текст із лапками залишається даними. Назви таблиць і полів
   є частиною структури SQL, їх не можна передати як значення параметра.
5. **Пакет.** Одна транзакція забезпечує все або нічого. Якщо робити
   commit після кожної вставки, попередні елементи залишаться після
   помилки наступного.
6. **with connection.** Підтверджує успішну транзакцію або скасовує її
   при винятку, але не закриває з'єднання. Для закриття використано closing.
7. **HTTP і SQL.** GET читає через SELECT, POST додає через INSERT,
   PUT змінює через UPDATE, DELETE видаляє. PUT у цій роботі замінює
   всі змінювані поля, тому всі вони обов'язкові.
8. **Де параметри.** `/records/1` — id у шляху;
   `/records?min_value=7` — параметр запиту; JSON нової знахідки — тіло.
9. **Pydantic.** Перевіряє типи, довжини після обрізання пробілів,
   діапазон 0–10, скінченність числа, статус, додатні id й зайві поля.
   Наявність категорії перевіряється вже в базі.
10. **response_model.** Описує й перевіряє структуру відповіді та формує
    документацію. RecordRead містить id і назву категорії з JOIN.
11. **id у створенні.** Його створює SQLite; клієнт не керує ключем.
    `extra="forbid"` відхиляє id у тілі нового запису.
12. **Коди HTTP.** 201 — створено; 204 — видалено без тіла; 404 — немає
    запису; 409 — дублікат або непорожня категорія; 422 — неправильні
    дані. 204 за своїм значенням не має тіла відповіді.
13. **Файли в Git.** SQL і seed дозволяють відтворити базу.
    Робочий SQLite-файл містить результати локальних запусків,
    змінюється під час роботи й не потрібен для відтворення.
