## Підготовка на Windows

Відкрий кореневу папку `cybersecurity-python-labs` у VS Code. У терміналі
**Command Prompt** виконай:

```bat
git pull
.venv\Scripts\activate.bat
python -m pip install -r requirements.txt
```

Якщо це нова копія репозиторію, перед активацією створи середовище:
`py -m venv .venv`. На Linux активація: `source .venv/bin/activate`.
Усі подальші команди виконуються з кореня репозиторію.

## Структура лабораторної

| Шлях | Призначення |
| --- | --- |
| `main.py` | Команди `demo` і `analyze` |
| `task1.py` | Класи User, Admin, Session, AuditLog, UserAccount |
| `task2.py` | Пошук PII, маскування та JSON-звіт |

Чотири вхідні файли взято без зміни байтів з `lab2_data.zip`.
Вкладеність каталогу `data_v13` збережено. Усі дані синтетичні;
програма нічого не надсилає в мережу й не змінює початкові файли.

## Демонстрація класів

```bat
python -m labs.lab02.main demo
```

Показуються неправильний і правильний паролі, зміна email та відмова для
неправильної адреси, надання й відкликання прав адміністратора,
індексатори та помилки ключів/типів, імітація таймауту, вихід, деактивація
та журнал аудиту UTC. Таймаут імітується зміщенням `last_activity` на
901 секунду, тому чекати 15 хвилин не потрібно.

`User` зберігає лише PBKDF2-HMAC-SHA256 і випадкову сіль 16 байтів;
кількість ітерацій задано константою `PASSWORD_ITERATIONS = 600_000`.
Email має відповідати саме спрощеній умові методички: локальна частина
3–64 символи, перша латинська літера, далі латинські літери, цифри або `_`.
Точки в локальній частині тут не дозволені, хоча сканер PII у завданні 2
виявляє й звичайні адреси з точками.

`is_authenticated()` перевіряє стан, але не викликає `touch()` і не
подовжує сеанс. Невдалий новий вхід завершує попередній сеанс.
Заміна користувача через `account["user"] = ...` теж скидає сеанс.
Індексатори дозволяють лише `user`, `session` і `audit_log`;
для `session` також дозволено `None`. Деактивація блокує як новий вхід,
так і автентифікацію за вже створеним сеансом.

## Сканування всіх типів

```bat
python -m labs.lab02.main analyze --scan-dir labs/lab02/data/data_v13/scan --patterns all --mask --out-json labs/lab02/data/pii_report.json
```

Очікувані результати саме для наданого архіву:

| Показник | Значення |
| --- | ---: |
| Прочитано файлів | 4 |
| Пропущено файлів | 0 |
| Email | 4 |
| Картки | 3 |
| Телефони | 4 |
| IPv4 | 4 |
| Усього збігів | 15 |

У кожному з файлів `export.json`, `app.log`, `users.txt` є 5 збігів;
у `clean.txt` немає жодного. Картка не рахується ще й телефоном.
Дати журналу не зараховуються до телефонів.

## Окремі типи та довідка

```bat
python -m labs.lab02.main analyze --scan-dir labs/lab02/data/data_v13/scan --patterns cards --mask --out-json labs/lab02/data/cards_report.json
python -m labs.lab02.main analyze --scan-dir labs/lab02/data/data_v13/scan --patterns emails --mask --out-json labs/lab02/data/emails_report.json
python -m labs.lab02.main --help
python -m labs.lab02.main analyze --help
```

Режим `cards` знаходить 3 картки; `emails` знаходить 4 адреси.
Телефони та IPv4 перевіряються в режимі `all`.

| Параметр analyze | Значення |
| --- | --- |
| `--scan-dir` | Обов'язкова папка для рекурсивного обходу |
| `--patterns` | `all`, `cards`, `emails`; типове значення `all` |
| `--mask` | Маскування значень у консолі |
| `--out-json` | Обов'язковий шлях до вихідного JSON |

**JSON-звіт завжди маскований**, навіть без `--mask`.
Без прапорця консоль показує початкові синтетичні значення.
У JSON записуються UTC-час, вибраний режим, кількість файлів,
підсумки за типами, відносний шлях, номер рядка й масковане значення.
У попередженнях `logging` є назва файла та кількість збігів, без самих PII.

## Пошук і обмеження

Збіги спочатку шукаються через регулярні вирази. Для IPv4 додатково
перевіряється діапазон октетів через `ipaddress`. Для карток перевіряються
довжина 13–19 цифр та контрольна сума Луна. Контрольна сума не доводить,
що картка існує: це спосіб зменшити кількість випадкових чисел.

Сканер читає UTF-8 текст, а не документи PDF або Word. Він виявляє
ознаки відкритих даних у файлах і не доводить факт їх передавання назовні.
PII визначаються за форматом, тому можливі хибні збіги та пропуски.
Довільні телефонні формати з інших країн можуть потребувати уточнення
правил. Результати не слід вважати повним аудитом конфіденційності.

## Обробка помилок

- Неправильні або відсутні аргументи: довідка `argparse`, код завершення 2.
- Відсутня папка або помилка запису: повідомлення ERROR, код завершення 1.
- Бінарні, не UTF-8 або недоступні файли: WARNING і пропуск файла.
- JSON-звіт усередині папки сканування виключається з обходу.
  Уже наявний вхідний JSON не можна перезаписати звітом.
- Символічні посилання не скануються.

Повторний запуск оновлює звіт, а вхідні файли зберігає.
Звіти `data/*_report.json` не додаються в Git завдяки `.gitignore`;
оригінальний вкладений `exports/export.json` є навчальним вхідним файлом.
