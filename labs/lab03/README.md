# Лабораторна робота 3 — варіант 13

Реєстр знахідок аудиту хмарної конфігурації. Категорії `iam`, `storage`,
`network` описують права доступу, сховища та мережеві налаштування.
`value` — навчальна оцінка ризику від 0 до 10 `score`. Поріг варіанта — 7.0;
це значення для фільтра `min_value`, а не заборона зберігати менші оцінки.
`status` має значення `new`, `in_progress` або `done`.

## Запуск у Windows

Відкрити корінь репозиторію у VS Code і термінал **Command Prompt**:

```bat
git pull
.venv\Scripts\activate.bat
python -m pip install -r requirements.txt
python -m labs.lab03.database
python -m labs.lab03.seed
python -m labs.lab03.seed
python -m uvicorn labs.lab03.main:app --reload --host 127.0.0.1 --port 8000
```

Повторний seed повідомляє, що база непорожня, і не змінює дані.
Під час запуску API створюються лише відсутні таблиці, початкові записи
автоматично не додаються. SQLite не потребує окремої програми чи сервера.

Відкрити:

- Swagger UI: http://127.0.0.1:8000/docs
- OpenAPI: http://127.0.0.1:8000/openapi.json

У Swagger розкрити маршрут, натиснути **Try it out**, заповнити поля й
натиснути **Execute**. Результат дивитися в **Server response**;
нижче також є приклади можливих відповідей, які не є результатом запиту.
Для завершення сервера натиснути `Ctrl+C` у його терміналі.

Linux/macOS: створити середовище через `python3 -m venv .venv`,
активувати `source .venv/bin/activate`; інші Python-команди такі самі.
Перевірено Python 3.12.14, FastAPI 0.162.0, Pydantic 2.14.1,
Uvicorn 0.54.0, Starlette 0.52.1, HTTPX 0.28.1 та Ruff 0.17.1.
HTTPX потрібен для автоматичних перевірок API через TestClient.

## Структура

- `database.py` — з'єднання та виконання наданого `schema.sql`.
- `repository.py` — SQL із параметрами `?`, JOIN, фільтри й транзакції.
- `schemas.py` — моделі Pydantic для запитів, відповідей і seed.
- `config.py` — одиниця вимірювання, діапазон і поріг.
- `seed.py`, `data/seed.json` — початкові 3 категорії та 8 знахідок.
- `routers/categories.py`, `routers/records.py` — синхронні HTTP-маршрути.
- `main.py` — FastAPI, lifespan, підключення маршрутів і HTTP-помилки.

У Git зберігаються SQL і seed, але не файл бази `data/lab3.sqlite3`.
Шляхи визначаються відносно модуля, без редагування `sys.path`.
Для повністю нової демонстраційної бази спочатку зупинити сервер,
зберегти потрібні дані й лише потім видалити `labs/lab03/data/lab3.sqlite3`
та виконати seed. Звичайний запуск базу не очищує.

## Маршрути

| Метод | Адреса | Результат |
| --- | --- | --- |
| GET | `/ping` | 200, стан сервісу |
| GET | `/student` | 200, ПІБ, група, варіант |
| GET | `/categories` | 200, список категорій |
| POST | `/categories` | 201, нова категорія |
| DELETE | `/categories/{category_id}` | 204, видалення порожньої категорії |
| GET | `/records` | 200, список із фільтрами |
| GET | `/records/{record_id}` | 200, знахідка з назвою категорії |
| POST | `/records` | 201, нова знахідка |
| PUT | `/records/{record_id}` | 200, повна заміна полів |
| DELETE | `/records/{record_id}` | 204, порожня відповідь |
| POST | `/records/bulk` | 201, список створених знахідок |

Відсутній запис або потрібна категорія — 404; дублікат чи видалення
непорожньої категорії — 409; помилка моделі або параметра — 422.
Технічні помилки SQLite журналюються, клієнт отримує загальне повідомлення.
З'єднання відкривається й закривається всередині кожної операції.

## Основні запити

Без параметрів `GET /records` показує 8 початкових знахідок.
`GET /records?category_id=1&status=new` повертає `V13-01`, `V13-04`.
`GET /records?min_value=7` повертає `V13-01`, `V13-04`, `V13-05`, `V13-07`.
`GET /records?limit=2&offset=2` повертає записи з id 3 і 4.
Фільтри поєднуються через AND. Сортування — за зростанням id.
`q` шукає буквальний підрядок із врахуванням регістру; `%` і `_` не є
шаблонами. Невідома додатна категорія у фільтрі дає порожній список.

Для `POST /records` вставити:

```json
{
  "code": "V13-09",
  "title": "Відкритий доступ до сховища",
  "category_id": 2,
  "value": 8.5,
  "status": "new"
}
```

З відповіді взяти `id`. Виконати `GET /records/{record_id}`.
У `PUT` передати всі п'ять полів, наприклад змінити `value` на `6.0`,
`status` на `done`. `id` у тілі не передавати.
Потім виконати `DELETE /records/{record_id}` — відповідь 204 без JSON.

Для категорії: `POST /categories` із `{"name":"backup"}`, потім DELETE
із отриманим id — 204. Видалення початкової категорії 1 — 409.
Повторна назва `iam` — 409.

## Пакет і відкат

У `POST /records/bulk` передати JSON-масив із 1–100 об'єктів.
Коректний пакет:

```json
[
  {"code":"BULK-01","title":"Перевірка прав доступу","category_id":1,"value":8.0,"status":"new"},
  {"code":"BULK-02","title":"Перевірка мережі","category_id":3,"value":5.0,"status":"new"}
]
```

Відкат через дублікат:

```json
[
  {"code":"ROLL-01","title":"Перевірка прав доступу","category_id":1,"value":8.0,"status":"new"},
  {"code":"V13-01","title":"Повторний код","category_id":2,"value":5.0,"status":"new"}
]
```

Очікується 409. Перед запитом і після нього виконати
`GET /records?limit=100`: кількість не зміниться, `ROLL-01` відсутній.
Для відкату через неіснуючу категорію взяти два нові коди, а другому
запису задати `category_id=999`: 404, обидва записи відсутні.
Окремі commit після елементів не виконуються — `with connection`
скасовує транзакцію при винятку; `closing` закриває з'єднання.

## Перевірки за методичкою

1. Seed двічі: 3 категорії, 8 записів, повтор без змін.
2. `/ping`, `/student`, `/categories`: 200 і правильні поля.
3. CRUD окремого запису: 201, 200, 200, 204.
4. Окремі та спільні фільтри; `limit` й `offset`.
5. `value=-1`, `title="   "`, `status="closed"`, `limit=0`: 422.
6. `value=10.1`: 422; `NaN` і нескінченність також не допускаються.
7. Запис 999 або `category_id=999` при створенні: 404.
8. Повтор `code=V13-01` і назви `iam`: 409.
9. Видалення непорожньої категорії: 409, порожньої: 204.
10. Коректний пакет із двох нових кодів: 201.
11. Дублікат у другому елементі: 409, відкат усього пакета.
12. Категорія 999 у другому елементі: 404, відкат усього пакета.
13. Фільтр `q` зі значенням `' OR 1=1 --`: 200 і порожній список.
14. Створити запис, перезапустити Uvicorn, прочитати той самий id: 200.

Не повторювати створення з тим самим code, очікуючи 201:
після першої успішної вставки наступна поверне 409.

```bat
ruff check labs/lab03
ruff format --check labs/lab03
ruff check .
ruff format --check .
python -m unittest discover -v
```

У тестах використовуються тимчасові бази; робочі дані не змінюються.
